# RV1 — Semantic annotation protocol

> **Disclosure.** The primary annotation set in this repository
> (`annotations/rv1/primary/`, assessor `openai-gpt-5.6-sol-primary`) was produced by GPT-5.6 Sol
> from the frozen RV0 traces, benchmark gold fields and the generated sheets. It is
> **model-assisted annotation, not independent human ground truth** and must not be described
> as human or expert annotation. The protocol below is written for any assessor; a human
> assessor can still be added with `rv1-add-assessor` for validation. A model assessor sees
> the whole file, so its `authored_before_viewing_generated` attestation is self-reported and
> not verifiable.

Status: 22 of 22 files complete (assessor above); validated and aggregated. Annotation
used no repository API calls and no LLM judge inside the tooling. Results:
[RV1 summary](RV1_SUMMARY.md). Part of the
[research validation plan](../../RESEARCH_VALIDATION_PLAN.md); builds on the frozen
[RV0 audit](RV0_PILOT_AUDIT.md) (commit `919e86d`), which is not modified.

All 22 pilot questions are annotated, in the RV0 priority order (order only; there is
no subset). These 22 questions are now **development/diagnostic data** and can never be
an untouched test set. RV3 and later use new, disjoint questions.

## What you fill in

One YAML file per question, 22 in total:

```text
annotations/rv1/primary/NN_<dataset>_<id>.yaml      NN = 01 … 22 (annotation order)
```

Each file has read-only `context` blocks (generated, hash-bound) and blank human
fields. Retrieved-document text, which is too long for the YAML, is in the matching
sheet under `artifacts/rv1-sheets/NN_<dataset>_<id>.md` (git-ignored and regenerated by
`rv1-init`). Read the sheet and the file side by side.

### Workflow per file

1. Set `assessor` (your id/initials), `date`, and `status: IN_PROGRESS`.
2. **Oracle first** (see below), before reading the generated decomposition. Then set
   `oracle.authored_before_viewing_generated` honestly. If you looked first, answer `NO`;
   that is recorded and the oracle can then be down-weighted.
3. Fill `decomposition` and each `premises[*].judgment`.
4. For each method (`epistemic_search`, then `premise_only`): `retrieval_rounds`,
   `extraction_batches` (and their `items`), `belief_states`, `controller_decisions`,
   `outcome`.
5. Fill `root_cause` for each method last. Do not infer it from the RV0 mechanical flags;
   those are context, not answers.
6. Set `status: COMPLETE` only when every field is answered.

Answers are `YES`, `NO`, `UNSURE`, plus `NOT_APPLICABLE` where a field offers it. `null`
means *not answered* and is never read as `NO`. Use `UNSURE` rather than guessing, and
the `notes` field for any convention you adopt. Unquoted `NO`/`YES` are safe (this
project's YAML reader does not turn them into booleans).

### Checks

```sh
uv run --locked epistemic-search rv1-validate configs/rv1.yaml                    # untampered + consistent
uv run --locked epistemic-search rv1-validate configs/rv1.yaml --require-complete  # also all 22 COMPLETE
uv run --locked epistemic-search rv1-aggregate configs/rv1.yaml                    # summary, oracle export
```

Validation rejects: edited `context` or hash, files that differ from
`docs/results/rv1/context_manifest.json`, missing/extra files, invalid enum values,
`COMPLETE` with any blank, and the consistency rules listed per field below.

## Field definitions

**Oracle (`oracle`)** — write from the question and gold answer / supporting facts only.
`required_claims`: list of `{id, assertion}` (ids like `o1`, `o2`; each assertion a
declarative sentence that must be established to answer). `logic.type`: `AND` (all
needed), `OR` (any one suffices), `NOT` (exactly one claim, whose negation is needed) or
`OTHER` (then `logic.description` is required). Keep it simple; do not formalise further.
Convertible oracles (`AND`/`OR` with ≥ 2 claims, `NOT` with 1) are exported as
`ProofGraph` objects in `docs/results/rv1/oracle_decompositions.jsonl` so RV2/RV3 can run
the same downstream system on the oracle decomposition. The comparison itself is not part of RV1.

**Decomposition** (shared by both methods; verified identical for all 22): `semantically_correct`
(captures what the question asks), `complete` (nothing required is missing),
`has_unnecessary_premises`, `has_missing_required_premises`,
`dependency_structure_matches` (the `formula` AND/OR/NOT structure matches what is
needed).

**Premise** (each generated claim): `is_assertion` (a declarative statement that can be
true or false, not a task like "Identify…", a question, or a "whether" clause),
`necessary` (needed to answer under a correct decomposition), `relevant` (bears on the
question, even if not necessary), `atomic` (one checkable proposition), `well_formed`
(self-contained and interpretable; a placeholder like "the director" counts only if the
decomposition binds it), `correct` (true given the gold facts; `NOT_APPLICABLE` for a
non-assertion or one whose truth depends on an unbound variable). The
`lexical_surface_form_flag` in the context is a fixed word-list flag, not a hint at the answer.

**Retrieval round** (one per search): `target_premise_appropriate` (`NOT_APPLICABLE` for
round 1, which uses the original question), `query_appropriate_for_target`,
`query_materially_different_from_previous` (`NOT_APPLICABLE` for round 1; from round 2 it
must be answered), `retrieved_docs_contained_needed_info` (needed to resolve the round's
target, or the question for round 1), `retrieved_set_contained_gold_supporting_evidence`
(`NOT_APPLICABLE` when the benchmark has no supporting-fact annotation, e.g. ConfRAG; the
context lists gold titles seen), `missing_info_retrievable_from_corpus` (`NOT_APPLICABLE`
if the retrieved documents already contained it; otherwise is the information in the
available benchmark corpus at all?).

**Extraction batch** (one claim × one document, including empty batches):
`decisive_evidence_present_in_document` and `decisive_evidence_missed_by_extraction`
(`NOT_APPLICABLE` if nothing decisive is present). This is recorded per batch rather
than per item because a missed item has no row.

**Evidence item** (each extracted span): `addresses_assigned_premise`, `gold_stance`
(`SUPPORT` / `CONTRADICT` / `NEUTRAL` / `UNSURE`, your own judgment of the span against
the premise, independent of the system's stance), `span_sufficient_alone`,
`span_meaning_faithful` (whether a span that is not verbatim still represents the
source; `NOT_APPLICABLE` for `EXACT`). `mechanical_span_class` (`EXACT`,
`NORMALIZATION_EQUIVALENT`, `NON_VERBATIM`) is computed, not judged.

**Belief state** (one per belief update, with the reasoner result that followed):
`claim_status_justified` (if `NO`, list the premise labels, e.g. `[P1]`, in
`unjustified_premise_labels`), `blockers_genuinely_blocking` (`NOT_APPLICABLE` if none),
`more_important_blockers_missing` (describe in `missing_blockers_description`),
`formal_conclusion_appropriate` (given **your** reading of premises and evidence, not the
system's). Scores in the context are uncalibrated heuristics, not probabilities.

**Controller decision**: `target_premise_appropriate`, `action_appropriate` (applies to
whichever of `SEARCH_MORE`, `RESOLVE_CONFLICT`, `ANSWER`, `ABSTAIN` was taken),
`repeat_justified` (required, not `NOT_APPLICABLE`, whenever the context says the next
query exactly repeats an earlier one), `better_action` (`NONE` if the choice was best).

**Outcome**: `answer_correct` (your judgment, independent of exact match;
`NOT_APPLICABLE` only if no answer was given), `abstention_appropriate` (`NOT_APPLICABLE`
only if an answer was given).

**Root cause (per method)**: one `primary` and optional distinct `secondary` labels from
`DECOMPOSITION_ERROR`, `RETRIEVAL_ERROR`, `QUERY_GENERATION_ERROR`,
`EVIDENCE_EXTRACTION_ERROR`, `STANCE_ERROR`, `BELIEF_AGGREGATION_ERROR`,
`FORMALIZATION_ERROR`, `CONTROLLER_ERROR`, `ANSWER_GENERATION_ERROR`,
`APPROPRIATE_ABSTENTION`, `MULTIPLE_FAILURES`, `NO_IDENTIFIED_FAILURE`, `UNCERTAIN`.
Guidance: choose the earliest stage whose failure by itself explains the outcome.
`QUERY_GENERATION_ERROR` is the wording of a query for a sensible target;
`CONTROLLER_ERROR` is the choice of target or action; `RETRIEVAL_ERROR` is the retriever
failing on an appropriate query. `MULTIPLE_FAILURES` needs two or more secondary labels.
`APPROPRIATE_ABSTENTION`, `NO_IDENTIFIED_FAILURE` and `UNCERTAIN` take no secondary labels,
and `APPROPRIATE_ABSTENTION` is rejected for an answered case. `rationale` is required.

## Workload, honestly

3,166 blank fields across the 22 files (about 140 per question; 195 extraction batches,
164 evidence items, 110 retrieval rounds, 110 decisions, 80 premises, 47 belief states).
Do not pad or skip to save time; `UNSURE` is acceptable and informative. Many premise-only
rounds repeat the epistemic-search round with the same query and documents; you may
answer them the same way, as a human decision, but no tool copies answers for you.

## Two assessors

For agreement, a second person runs
`uv run --locked epistemic-search rv1-add-assessor configs/rv1.yaml <id>`, which creates
`annotations/rv1/<id>/` from the identical hash-checked context. `rv1-aggregate` then
reports per-section raw agreement and Cohen's kappa and writes `disagreements.jsonl`. With
one assessor, re-labelling about 20% of questions after at least a week is the proposed
intra-rater check. With 22 questions, report counts, not precise percentages.

## Outputs

`docs/results/rv1/`: `context_manifest.json` (hash of each file's read-only context, bound
to the frozen RV0 outputs), `summary.json` (completeness; the failure distribution and
section tables appear **only** when an assessor has completed all 22 cases),
`oracle_decompositions.jsonl`, `disagreements.jsonl`. Aggregation is deterministic and
rewrites only these results, never the annotations.

## Rules during RV1

No code, prompt or threshold changes. No RV2 fixes until annotation is complete and
aggregated. No new API calls. The RV0 outputs and the `rv1_annotation_template.jsonl`
that RV0 emitted are frozen; the template is superseded by the files above and is not used.
